# DECIPHER microservice data model

The diagram below shows the data schemas used across the DECIPHER microservice. These include models for API request and response validation, as well as the dataclasses used in the scoring engine. The relationships between these models are also depicted, illustrating how data flows through the system from input to analysis results.

```mermaid
%% DECIPHER data model — Pydantic API models, scoring engine dataclasses, and config

erDiagram

    %% ── API layer ──────────────────────────────────────────────────────────

    IncidentRequest {
        str     priority_level  "MISP priority-level taxonomy, required"
        str     title           "optional, default assigned if absent"
        str     template_id     "optional, case template identifier"
        dict    extra           "optional additional fields for case description"
    }

    IncidentResponse {
        int     id          "Flowintel case ID"
        str     link        "direct URL to case"
    }

    AnalysisResult {
        str     analyzed_scenario
        float   severity            "0.0–1.0"
        dict    report              "analyzer-specific details"
        dict    created_case        "id + link"
    }

    %% ── Analyzer input schemas ─────────────────────────────────────────────

    SuspiciousLoginAlert {
        str         username
        str         target_host
        list_str    src_ips
        str         timestamp       "ISO 8601"
    }

    CaseTemplate {
        str     title
        str     filename
    }

    %% ── Scoring engine dataclasses ─────────────────────────────────────────

    EventData {
        int             id
        ThreatLevel     threat_level
        AnalysisStage   analysis
        bool            has_mitre_tags
    }

    AdmiraltyTags {
        SourceReliability   source_reliability  "A–G or absent"
        InfoCredibility     info_credibility    "1–6 or absent"
    }

    AttributeData {
        str     value
        str     type
    }

    Sightings {
        int     true_positives
        int     false_positives
    }

    EventScoreResult {
        int     event_id
        float   score
        float   severity
        float   confidence
        float   threat_level_value
        float   tags_multiplier
        float   c_analysis
        float   c_evidence
    }

    AttributeBreakdown {
        float   c_sightings
        float   c_admiralty
        float   c_attr
    }

    FinalScoreResult {
        float   score
    }

    ScoringConfig {
        float   tags_multiplier
        float   w_analysis
        float   w_empirical
        float   w_sightings
        float   w_admiralty
    }

    %% ── Relationships ──────────────────────────────────────────────────────

    SuspiciousLoginAlert ||--|| AnalysisResult       : "produces"
    AnalysisResult       }o--o| IncidentRequest      : "triggers (optional)"
    IncidentRequest      ||--|| IncidentResponse     : "creates"

    FinalScoreResult     ||--|{ EventScoreResult     : "aggregates"
    EventScoreResult     ||--|{ AttributeBreakdown   : "breaks down"

    EventData            ||--o| AdmiraltyTags        : "event-level admiralty"
    EventData            ||--|{ AttributeData        : "contains"
    AttributeData        ||--|| Sightings            : "has"
    AttributeData        ||--o| AdmiraltyTags        : "attribute-level admiralty"

    EventData            ||--|| EventScoreResult     : "scored into"
    ScoringConfig        ||--|{ EventScoreResult     : "parameterises"

    IncidentRequest      }o--o| CaseTemplate         : "selects (optional)"
```
