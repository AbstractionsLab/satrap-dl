# Analysis endpoint: `suspicious_login` request flow

The sequence diagram below details the successful flow for `POST /api/v0.1/analyze/suspicious_login`. The Flowintel case creation step is abstracted as a single interaction; The erroneous paths correspond to those detailed in SWD-008.

The data schema bound to the `suspicious_login` alert type is `SuspiciousLoginAlert` as shown in SWD-013.

**Preconditions:** alert data passes schema validation, MISP search is enabled and reachable, case creation is optionally enabled or disabled per configuration.

```mermaid
sequenceDiagram
    actor Client
    participant API as API (api.py)
    participant Registry as AnalyzerRegistry
    participant Analyzer as SuspiciousLoginAnalyzer
    participant RuntimeCfg as runtime_settings.py
    participant MISP as MISP (MISPEnrichmentMixin)
    participant Scoring as Scoring Engine
    participant Flowintel as Flowintel

    Client->>API: POST /api/v0.1/analyze/suspicious_login {username, target_host, src_ips, timestamp}
    API->>Registry: analyze("suspicious_login", data)
    Registry->>Registry: validate data against SuspiciousLoginAlert schema
    Registry->>Analyzer: analyze(SuspiciousLoginAlert)
    Analyzer->>RuntimeCfg: load_decipher_runtime_cfg()
    RuntimeCfg-->>Analyzer: config (enable_misp_search=True, enable_case_creation=...)
    Analyzer->>MISP: search_iocs_in_misp({ip-src, ip-dst, target-user})
    MISP-->>Analyzer: [EventData list]
    Analyzer->>Scoring: score_events(event_data)
    Scoring-->>Analyzer: FinalScoreResult {score, breakdown}
    alt enable_case_creation = True
        Analyzer->>Flowintel: create_case_for_scenario(scenario, description, score)
        Flowintel-->>Analyzer: case_id
    else enable_case_creation = False
        note over Analyzer: case creation skipped per config
    end
    Analyzer-->>Registry: AnalysisResult {severity, report, created_case}
    Registry-->>API: AnalysisResult
    API-->>Client: 200 OK AnalysisResult
```
