# DECIPHER service: incidents endpoint

_As a_ security engineer, _I want_ to use the incidents endpoint of the DECIPHER service for creating a case in Flowintel by providing a priority level and data for informing the case, _so that_ I can automatically escalate incidents as part of my incident handling workflow.

I want the incident creation endpoint to:

1. Accept a POST request with all the case information in a JSON payload.
2. Accept in the body of the request a priority level from the [`priority-level` MISP taxonomy](https://www.misp-project.org/taxonomies.html#_priority_level). These levels are defined in the context of a National Cyber Incident Scoring System (NCISS), yet, we consider this classification general enough to be used as a reference and applied in other contexts.
3. Reject requests with an invalid priority level with a clear validation error.
4. Accept in the request body the following optional elements:
	- A custom title for the case. If not provided, the endpoint should assign a default title.
	- The identifier of a case template to be used if available.
	- A JSON object containing additional key-value pairs to be included in the Flowintel case description.
5. Create a case in Flowintel using the selected case template if available, otherwise, create a case without a template.
6. Add the JSON bundle referred in (4) in a readable format into the case description.
7. Assign the case a priority tag corresponding to the provided priority level.
8. Return the created case ID and a direct URL to the case in Flowintel.

### Rationale
Decoupling case creation from the internal analysis workflow allows external tools (e.g. SIEM active responses, SATRAP notebooks, third-party SOAR playbooks) to integrate DECIPHER's incident creation as part of existing workflows. This broadens the interoperability of the SATRAP-DL ecosystem.

### Acceptance criteria
1. A POST request to the incident endpoint with a valid priority tag returns HTTP 200 with a JSON response containing `id` (non-zero integer) and `link` (string starting with the configured Flowintel base URL).
2. A POST request to the incident endpoint with an invalid priority tag returns HTTP 422 with a validation error message.
3. The priority tag of the created case corresponds to the priority level sent in the request.
4. Additional fields provided in the request body appear in the case description in Flowintel.
