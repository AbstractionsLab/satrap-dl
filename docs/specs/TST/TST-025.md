# Test incidents endpoint

Validate the DECIPHER incidents endpoint for creating prioritized cases in Flowintel from an externally provided MISP priority level and optional case data.

## Preconditions and setup actions
- Docker Engine (or daemon) running with execution privileges for the testing user
- A reachable Flowintel instance set in `config/decipher-settings.yaml` with a valid API key
- DECIPHER stack running
- Access to a shell with `curl`

## Test steps

### AC1: Valid incident creation

1. Send the following POST request to the incidents endpoint:

```
curl -w " HTTP %{http_code}" \
  -X 'POST' \
  'http://localhost:8000/api/v0.1/incident' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{
  "priority_level": "priority-level:high",
  "title": "Brute force attempt detected",
  "description": {
    "source_system": "SIEM-001",
    "affected_user": "admin"
  }
  }'
```

2. Verify that the printed output contains `HTTP 200`.
3. Verify that the response body contains:
    - `id`: a non-zero integer (the Flowintel case ID)
    - `link`: a string starting with the configured Flowintel case URL (e.g. `http://localhost:7006/case/<id>`)
4. Access the created case in Flowintel using the returned `link` and verify that it exists.
5. Verify that the title of the case in Flowintel matches the `title` field provided in the request body with the string `[DECIPHER]` as a prefix and a timestamp as a suffix.

### AC2: Invalid priority level rejection

1. Send a POST request with a priority level that is not a valid MISP `priority-level` taxonomy tag:

```
curl -w " HTTP %{http_code}" \
  -X 'POST' \
  'http://localhost:8000/api/v0.1/incident' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{
  "priority_level": "unclassified"
  }'
```

2. Verify that the printed output contains `HTTP 422`.
3. Verify that the response body contains a validation error message referencing the `priority_level` field.

### AC3: Priority tag matches requested priority level

1. Send a POST request with `priority_level` set to `priority-level:severe`:

```
curl -w " HTTP %{http_code}" \
  -X 'POST' \
  'http://localhost:8000/api/v0.1/incident' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{
  "priority_level": "priority-level:severe"
  }'
```

2. Verify that the printed output contains `HTTP 200`.
3. Open the created case in Flowintel using the returned `link` and verify that it carries the `priority-level:severe` tag.

4. Send a POST request with `priority_level` set to `low`:

```
curl -w " HTTP %{http_code}" \
  -X 'POST' \
  'http://localhost:8000/api/v0.1/incident' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{
  "priority_level": "low"
  }'
```

5. Verify that the printed output contains `HTTP 200`.
6. Open the created case in Flowintel and verify that it carries the `priority-level:low` tag.

### AC4: Case description

1. Send a POST request with a `description` object containing additional key-value pairs:

```
curl -w " HTTP %{http_code}" \
  -X 'POST' \
  'http://localhost:8000/api/v0.1/incident' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{
  "priority_level": "priority-level:medium",
  "title": "Suspicious login from unknown IP",
  "description": {
    "source_system": "SIEM-001",
    "affected_user": "jsmith",
    "notes": "Multiple failed attempts followed by successful login"
  }
  }'
```

2. Open the created case in Flowintel using the returned `link`.
3. Verify that the case description contains the fields provided in the `description` object: `source_system`, `affected_user`, and `notes`.

## Expected outcome

**AC1:** All the validations in steps 2 to 5 succeed.

**AC2:** Successful validation on steps 2 and 3.

**AC3:** The priority tag of each created case matches the `priority_level` sent in the request; steps 2, 3, 5 and 6 are successfully validated.

**AC4:** The `description` fields from the request body appear in the case description in Flowintel.
