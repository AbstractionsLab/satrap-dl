# Retrieve software identification details

Validate that any deployment build of SATRAP-DL provides accessible means to retrieve version and identification details through both CLI and REST API interfaces.

## Preconditions and setup actions
- Docker Engine (or daemon) running with execution privileges for the testing user
- SATRAP running in a Dockerized environment (see the [SATRAP README - Getting started](https://github.com/AbstractionsLab/satrap-dl/blob/main/satrap/README.md#getting-started))
- DECIPHER REST service running at http://localhost:8000 (see the [DECIPHER README - Getting started](https://github.com/AbstractionsLab/satrap-dl/tree/main/decipher#getting-started)).
_Note: if a different host/port is used, update the test steps accordingly_
- Access to a shell with `curl` and standard CLI tools
- Access to a web browser

## Test steps

1. From the project root folder, execute the SATRAP CLI command:

	`./satrap.sh --version` or `./satrap.sh -V`

2. Send a curl request to the root endpoint of the DECIPHER REST API:
	`curl http://localhost:8000`

4. In a web browser access the URL: `http://localhost:8000/docs`


## Expected outcome

1. Both commands return: `SATRAP v1.0`.
2. The response body corresponds to the following JSON structure:
```json
{
  "service": "DECIPHER Analysis API",
  "version": "v1",
  "docs": "/docs",
  "redoc": "/redoc",
  "health": "/health",
  "analyzers": "/api/v1/analyzers"
}
```
3. The DECIPHER API docs are accessible and clearly show the version `v1` in the title and in the endpoint's URLs, e.g., `/api/v1/incident`
